# P04 security review, pass 1

Range 82f8d74..88d1676. Files: Hubs/AgentHub.cs, AgentHeartbeatValidator.cs, AgentHeartbeatMapper.cs, Program.cs, AgentHubTests.cs.

## Verdict

fix

Identity handling is sound: the node ID comes only from the `node_id` claim that `MtlsMiddleware` sets after chain, issuer, EKU, SPIFFE and trust-domain checks. The payload carries no node ID, the hub is mapped with `RequireAuthorization("AgentPolicy")`, and `MtlsMiddleware` covers `/hubs/agent` and its sub-paths by whole segment (`negotiate` included). A request with no certificate never gets a user, so `RequireAuthenticatedUser` rejects it. `EnableDetailedErrors` is false and the receive size is capped at 64 KiB. The two findings below are about what happens after the connection is accepted, and about unvalidated strings.

## Fix notes

N1. src/Dhadgar.Nodes/Hubs/AgentHub.cs:49 — The certificate is validated once, when the connection is accepted. `Heartbeat` then trusts `Context.User` for the life of the WebSocket. Inputs: (a) an operator revokes the agent certificate (`AgentCertificates.IsRevoked = true`); (b) the certificate passes `NotAfter`; (c) the node is decommissioned. The already-open connection keeps writing heartbeats, so a stolen or revoked certificate keeps working until the socket drops. Case (c) returns `node_decommissioned` but leaves the connection open. `HeartbeatService` checks node existence and decommission only, and `CertificateValidationService` is never called again — change: in `Heartbeat`, before `ProcessHeartbeatAsync`, read the `certificate_thumbprint` claim (set by `MtlsMiddleware`) and reject if `NodesDbContext.AgentCertificates` has a row with that thumbprint and `IsRevoked`. Use the same lowercase SHA-256 hex form the CA stores; confirm that in `CertificateAuthorityService.CalculateSha256Thumbprint`. Return `AgentHubErrorCodes.HeartbeatFailed` (or a new code in Contracts) and call `Context.Abort()`. Also call `Context.Abort()` when the result is `node_decommissioned` or `node_not_found`. For expiry, add a `certificate_not_after` claim in `MtlsMiddleware` (the `NotAfter` value from the validation result is already available there) and abort when `timeProvider.GetUtcNow()` is past it, unless `MtlsOptions.AllowExpiredCertificates` is set. The claim is a small edit outside P04's files, so if it is out of scope, record the expiry gap as a decision for the orchestrator — verify: tests (1) enroll, connect, revoke the certificate through the existing revoke path, invoke `Heartbeat` again: ack is `Acknowledged=false` and the connection closes (`connection.Closed` fires); (2) advance `TimeProvider` past `NotAfter` on an open connection: same result; (3) decommissioned node: connection closes after the first ack.

N2. src/Dhadgar.Nodes/Hubs/AgentHeartbeatValidator.cs:34 and :46 — `AgentVersion` and each `HealthIssues` entry are checked for length only. Inputs: `AgentVersion = "1.0\0"` passes the validator. `HeartbeatService` stores it with `node.AgentVersion = request.AgentVersion`, and Npgsql rejects NUL in text (22021) in `SaveChangesAsync`. The exception escapes the hub method as a `HubException`, which breaks R-RESULT, and the agent can repeat it every heartbeat. A `HealthIssues` entry such as `"ok\n2026-10-27 WARN Node <other-guid> recovered"` is joined into the `NodeDegraded` log line at Warning (`HeartbeatService.cs:243`) and forges a second log line. `AgentVersion` is also shown to operators — change: in `AgentHeartbeatValidator`, reject any `AgentVersion` or `HealthIssues` entry containing a control character (`char.IsControl`, which covers `\0`, `\r`, `\n`). Optionally require `AgentVersion` to match `^[0-9A-Za-z.+_-]{1,50}$`. Add the same rule for `HealthIssues` entries as far as the contract allows — verify: unit test `IsValid` returns false for `"1.0\0"`, `"1.0\n"` and an issue string containing `\r\n`, and true for `"2.0.0-hub"`. Add a hub test that sends the NUL version and gets `InvalidHeartbeat` with the database unchanged.

N3. tests/Dhadgar.Nodes.Tests/Hubs/AgentHubTests.cs — the tests cover the happy path, out-of-range CPU, decommissioned, and a bad protocol header. None of them covers the auth boundary this packet adds. Missing cases: connect with no certificate; connect with a certificate from a different CA; connect with a revoked certificate; a payload that tries to name another node — change: add three connection tests asserting `StartAsync` fails with HTTP 401 for no certificate, a foreign CA certificate and a revoked certificate, and one test where node A's certificate sends a heartbeat and only node A's `LastHeartbeat` changes while a second enrolled node stays untouched — verify: the four tests fail if `.RequireAuthorization("AgentPolicy")` is removed from `MapHub` or if `HubPathPrefix` stops covering `/hubs/agent`.

## Not fixed

- Pre-existing, now reachable from the hub: `CertificateAuthorityService.ValidateCertificateAsync` accepts any CA-signed certificate without an `AgentCertificates` row, and nothing binds the SPIFFE node ID to a stored thumbprint for the node. The hub inherits this. Decision for the orchestrator: bind the thumbprint to the node row in `CertificateValidationService`, or accept it because only the CA signs certificates. Not a P04 change.
- No per-connection heartbeat rate limit. A legitimately authenticated agent can loop `Heartbeat` and cause one DB read, one write and possibly an outbox publish per call. The 64 KiB message cap bounds size only. Low risk (the caller is an enrolled node). Consider a minimum interval per node in P05 or the commands campaign.
- `MtlsMiddleware` is disabled when `Mtls:Enabled=false` (Development only), and the hub then rejects everyone through `RequireAuthenticatedUser` rather than failing open. Good, but it means local hub use needs mTLS on.
- Gateway exposure of `/hubs/agent` and the `X-Client-Cert` stripping are covered by P03 and P06, not re-reviewed here. Seam test with simultaneous HTTP/2 streams is still worth asking for in P07.
